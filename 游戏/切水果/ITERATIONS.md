# 阶段迭代记录

目标：默认追踪手掌移动刀片，优先保证轨迹正确、设置可用、资源有界和启动稳定。

## 第一轮：启动与轨迹正确性

- 在加载摄像头库前预留 HTTP 端口，识别同项目服务并复用。
- 使用跨进程摄像头文件锁，避免不同端口的两个游戏服务重复打开同一设备。
- 输入层保留一帧内的多个位置样本，正确处理折线路径；样本缓冲有上限，积压、丢包、重新出刀均断开旧轨迹。
- 当时 13 项 Python、6 项 JavaScript 测试通过。

## 第二轮：测量与动态平滑

- 增加采集、推理、预览、处理、等待发送阶段的有界 P50/P95 指标；后续审查改用高精度 perf_counter 统一计时。
- 默认 One Euro 动态平滑，保留经典 EMA 选项；选择出刀动作不再使可见刀片发生平滑重置跳动。
- 固定随机种子的 30Hz 合成回放：静止抖动 0.002140 → 0.001603，运动平均绝对误差 0.020632 → 0.010776；均为归一化坐标，不是实机端到端延迟。
- 增加跨 15/30/60Hz 的停止后不过冲测试；修复浮点计算到达静止位置后的微小回退，相关 4 项测试通过。
- 一次真实摄像头检查正常，采集约 10 FPS；当次初版指标显示采集耗时远高于推理。不能据此保证所有现场都能达到目标帧率。

## 第三轮：标定与运行稳定性

- 两点操作范围标定、横纵独立灵敏度、个人映射保存与加载。
- 修复暂停后的连击时钟、重复打开暂停面板、切后台时停游戏、损坏排行榜数据和存储不可用的处理。
- 水果对象池上限 48；重复使用果汁与爆炸发射器并设置粒子上限；修复粒子位置重复偏移和菜单纹理重复生成。
- 标定与输入 JavaScript 共 9 项通过；后续完整浏览器复测确认标定、个人映射、暂停、对象复用和异常存储处理可用。

## 第四轮：低等待推送、部署与最终复审

- 将固定频率轮询改为新识别结果事件唤醒，保持最新帧邮箱和独立状态心跳；精简游戏消息，预览继续在本地画骨架。
- 统一高精度计时，并在超过 2 秒未返回新帧时报告采集/识别停滞。
- 创建项目独立虚拟环境，锁定已验证的 Windows / Python 3.12 依赖；启动器首次自动准备环境，后续始终使用同一解释器。
- 修复依赖文件被旧 pip 按 GBK 解码的问题；已有虚拟环境与引导 Python 版本不同时，按实际目标解释器选择依赖文件。
- 复查修正排行榜保存后的筛选标签显示；补充现有浏览器流程断言。
- 最终基础检查为 19 项 Python、9 项 JavaScript，另有语法、依赖完整性和批处理编码检查，全部通过。
- 真实 cmd 启动与重复启动通过；最终独立环境上的 Edge 流程与交互回归均无页面脚本错误。
- 15 次场景重开后，以加快水果生成的演示模式真实持续运行 180 秒，切果 2378 个；水果池、物理对象与粒子发射器数量保持有界。
- 独立环境摄像头复测收到 319 帧消息，约 29.9 FPS，预览 HTTP 200；服务端等待发布 P50/P95 为 0.19/0.33ms。画面未检测到手，因此不作为真人体验验收。

## 阶段结论

本机单人版已完成本阶段实现和可自动验证的验收，保留掌心追踪移动刀片的默认交互。当前测得约 30 FPS，暂不增加采集/推理线程拆分的复杂度；更长时间、多设备与真人手感验证作为下一阶段优先项。指标、运行条件和限制详见 [TESTING.md](TESTING.md)。

## 当前阶段验收要求

- 全部算法、协议、设置、设备恢复与启动检查通过。
- Edge 完整流程、标定、对象复用、暂停与反复场景切换通过，无页面脚本错误。
- 做有界资源的持续运行与压力检查，记录真实时长和模拟时长，不能混淆。
- 实机验证服务状态与预览；未完成的真人手感与跨设备验证明确列出。
- 文档与实际行为一致，Windows 批处理仍保持 ASCII / CRLF。

单人版本达到上述验收标准后作为阶段交付。双人计分、原生架构迁移和跨电脑打包不属于本阶段必要条件。
