# 疯狂切水果 · 手势识别版

用于社团招新展台的本地手势切水果游戏。Python 读取摄像头，MediaPipe 识别手部，浏览器运行 Phaser 游戏。鼠标操作随时可用。

默认操作是 **追踪手掌中心移动刀片**：手向哪里移动，刀片就跟向哪里，无需摆特定手势。刀尖光圈是切果的碰撞位置，刀片朝向随移动方向转动。优化路线和替代技术栈见 [OPTIMIZATION.md](OPTIMIZATION.md)。

当前问题、下一轮优化顺序和可逐项操作的排错清单见 [项目审查报告](PROJECT_REVIEW.md)（2026-10-16）。

## 启动

推荐 Python 3.12（代码要求 3.10+），Windows、摄像头、Chrome / Edge。

双击 `start.bat`：首次自动创建项目内的 `.venv` 并安装依赖，随后始终用它启动服务和打开浏览器。首次安装需要联网；不向全局 Anaconda 安装或删除包。Windows / Python 3.12 使用已验证的 `requirements-lock.txt`，其他版本使用 `requirements.txt` 解析兼容依赖。

也可在项目目录执行：

```powershell
python setup_env.py
.venv\Scripts\python.exe backend/main.py
```

访问 `http://127.0.0.1:8000`。服务默认只监听本机。首次启动若没有模型，会在后台下载约 8MB 的模型，菜单和鼠标玩法仍可使用。

```powershell
# 指定摄像头和端口，不自动打开浏览器
.venv\Scripts\python.exe backend/main.py --camera 1 --port 8001 --no-browser

# 无摄像头环境：只玩鼠标 / 演示，不加载模型、不打开摄像头
.venv\Scripts\python.exe backend/main.py --no-camera
```

`--camera` 会覆盖本次启动的已保存摄像头编号。未传入时使用页面保存的设置，首次默认为 0。

重复启动同一端口会复用本项目服务，本次参数不覆盖已运行服务；不同端口的游戏服务通过设备锁避免重复打开同一摄像头。更改启动参数时请先关闭旧服务。

## 调好手势再开始

1. 打开主菜单左下方的 **控制方式**，选择 **手势识别**。
2. 预览里应能看到摄像头画面。把整只手放入画面，出现骨架即表示识别成功。
3. 默认镜像开启，绿色虚线框对应游戏全屏；手在框内移动即可覆盖屏幕。
4. 选择出刀方式，点击 **应用识别设置**。预览绿圈表示出刀，黄圈表示识别到手但未出刀。
5. 点击 **完成**，选择无尽 / 限时 / 演示，开始游戏。

| 出刀方式 | 操作 |
| --- | --- |
| 跟手出刀 | 默认方式，持续跟随手掌移动刀片，无需捏合或伸指 |
| 伸食指出刀 | 食指伸直时切果，收起食指可移动手而不切果 |
| 捏合出刀 | 拇指和食指捏合后挥动切果，松开停刀 |

伸指与捏合由关键点几何关系判断。捏合阈值按掌部大小归一化，并使用不同的开合阈值减少抖动；遮挡、侧手或光线差时仍可能漏检。

| 设置 | 使用方式 |
| --- | --- |
| 摄像头编号 | 0 通常是默认摄像头；切换编号后点击应用，无需重启 |
| 识别灵敏度 | 默认「较高（推荐）」；有画面但没有骨架时可试「更高」，背景误识别时调回「标准」；点击应用后短暂重载模型 |
| 追踪位置 | 默认手掌中心，也可选食指指尖 / 中指指尖 / 手腕；选择即保存并应用，无需另点应用按钮。查看「当前追踪」和预览光圈确认生效；可选出刀动作仍按食指与拇指判断 |
| 跟手程度 | 越高响应越快，越低越平滑；默认 0.5 |
| 平滑算法 | 默认动态平滑（One Euro），静止时抑制抖动、快速移动时提高响应；可切换经典 EMA 对比 |
| 横向 / 纵向灵敏度 | 分别调整，默认 1.0，覆盖整个摄像头画面；调高会缩小有效范围，边缘不跟手时点击「恢复全画面」或重新标定 |
| 左右 / 上下中心偏移 | 调整有效区域，适应摄像头偏放或玩家站位 |
| 捏合容差 | 越大越容易触发捏合，默认 0.4 |
| 目标帧率 | 控制采集上限；实际帧率取决于摄像头和推理性能 |

镜像、横纵移动灵敏度、中心偏移即时生效并保存在浏览器。追踪位置选择后自动写入 `backend/settings.json`，即使随后点击「完成」也会继续保存；其他识别参数需点击应用。追踪点切换由摄像头线程接收并重置刀轨，不会把掌心到指尖的位置跳变作为挥刀；切摄像头或重载模型时会短暂停止出刀。识别灵敏度对应手掌检测阈值（较高 0.35、标准 0.5、更高 0.25），关键点存在与跟踪阈值保持 0.5。旧设置文件自动补齐新参数。

点击 **标定操作范围**，依次把手放在舒适活动范围的左上角和右下角，按提示稳定停留。标定根据新收到的手部坐标计算横纵映射；丢手、抖动过大或范围太小时保留原设置。可 **保存个人映射**，下次 **载入个人映射** 后快速恢复；更换镜像方向后请重新确认范围。展开 **摄像头与性能设置** 可切换设备、调整帧率，并查看采集、推理和等待发送的 P50/P95 耗时。

游戏中点击底部 **设置 / 暂停** 或按 **Esc** 打开设置，期间暂停物理、倒计时和连击计时；关闭后继续。切到其他标签页也会暂停。可在局内切换手势 / 鼠标，或点击 **返回菜单**。鼠标移动即切果，无需按键。

界面采用深色果园配色、青柠绿主按钮和本地 SVG 水果插画。设置按出刀跟随、操作范围和设备性能分组；窄屏可纵向滚动，底部完成按钮保持可见。模式卡片支持键盘选择，弹窗内 Tab 循环，Esc 关闭设置或排行榜；系统开启减少动态效果时会关闭装饰动画。

## 规则与规划落地

- **无尽**：5 次机会，切炸弹扣 1 次，漏果不扣机会。
- **限时**：60 秒，切炸弹扣 10 分，漏果扣 5 分，分数最低为 0。
- **演示**：AI 自动切果；真人移动鼠标或手势出刀时让出操作，停止操作 2 秒后继续演示。
- **计分**：水果基础 10 分，1.8 秒内连续切果形成连击，每 3 连击增加倍率，最高 5 倍。
- **排行榜**：浏览器本地保存昵称和各模式 Top10；清除浏览器数据会清除记录。
- **视觉**：本地 SVG 主菜单插画、程序绘制水果、青柠/珊瑚色刀锋拖尾、果汁粒子、爆炸、震屏和合成音效；Phaser 已随项目提供，无 CDN 依赖。
- **双人对战**：依照原规划继续保留多输入扩展接口，本期为单人游戏，尚未实现分屏与双人计分。

原规划在 `.codebuddy/plans/`，其中 handpose_x 路线为历史设计。当前入口采用 MediaPipe Tasks，不需要 PyTorch 或 handpose_x 权重。`backend/handpose_x/`、`handpose_engine.py`、`hand_detector.py` 保留为历史参考，不在主运行链路中，旧引擎不再受当前配置支持。

## 工作原理

```text
OpenCV 摄像头 → MediaPipe 21 关键点 → 伸指/捏合判定
                                      ↓
                         坐标平滑 + 出刀状态 + 轨迹编号
                                      ↓ WebSocket
                        镜像 / 灵敏度 / 中心偏移映射
                                      ↓
鼠标 / AI → BladeInput → BladeManager → 线段与水果圆碰撞 → 计分、特效、排行
```

采集、推理和预览编码共用一个后台线程，模型加载不会阻塞 HTTP 页面。新结果通过事件唤醒推送，WebSocket 仅保留最新待发帧，避免慢客户端积压旧轨迹；游戏消息不再传输预览才使用的整套骨架。状态心跳独立于采集结果，即使没有摄像头也会持续报告。

手掌中心取手腕与四个指根（0、5、9、13、17）的平均位置，不把容易随屈伸改变位置的指尖纳入中心计算。选择伸指或捏合模式时，刀片仍持续跟随手移动，仅切果状态由动作开关控制。配置中的 `blade_point_index=-1` 表示手掌中心，0~20 仍表示具体关键点。

快速挥动时，如果近期仍在跟踪手部但当前局部跟踪漏检，会对同一张画面补检一次；成功后保持刀轨连续，单人模式也不再仅因位移较大就断开轨迹。补检失败会立即停刀，并限制后续失败重试频率；不会沿用旧坐标模拟出刀。补检增加部分帧的推理耗时，无法保证恢复严重运动模糊或遮挡中的手。

丢失手部立即停刀；断线或 300ms 没有新坐标时前端也会停刀。再次识别、重新捏合、切换设置和窗口缩放会重置轨迹连接，避免跨屏误切。有效出刀时，水果碰到刀尖光圈或银色刀刃即可切开，即使手暂时停住也会判定接触；待机、失手、坐标过期时不切割，刀柄不参与切割。

水果判定范围按可见果肉半径计算，随缩放变化；挥动轨迹有 14px 半径，与刀尖光圈对应，银色刀刃按实际旋转后的轮廓检测，避免“画面重合却漏切”。炸弹按可见弹体的半径和旋转中心偏移检测。

刀尖坐标在屏幕边缘保留 24px 显示余量，跟手光圈、游戏刀尖与碰撞使用相同坐标。旧版未标定的默认 1.4 倍映射自动升级为全画面映射；自定义标定保留，新版本手动选择的 1.4 倍也会保留。跟手提示不会拦截鼠标操作。

前端保留单个渲染帧内的折线样本，按实际路径检测碰撞；丢包或样本积压时断开旧线段。水果对象池最多 48 个，粒子发射器复用并限制粒子数，减少持续游玩的对象分配。

游戏内右上方显示「你的手 → 刀锋」小预览：手部光圈与刀锋用虚线连接，镜像方向和操作框跟随当前映射；提示会随掌心/指尖追踪、跟手/伸指/捏合模式变化。可关闭连线或收起预览。小屏不再显示会遮挡预览的旧居中提示。

预览使用同一个 Python 摄像头，不向浏览器请求摄像头权限。仅在游戏手势预览展开或设置面板打开时拉取；暂停、菜单、结算、鼠标模式、页面进入后台时停止游戏预览。后端 JPEG 与控制点元数据使用同一帧快照，光圈不会错配到较新的坐标。后端不将摄像头画面保存到磁盘或上传到外部服务。

## 模型与离线使用

模型查找顺序：

1. `backend/models/hand_landmarker.task`（手动放置优先）。
2. 用户目录的 `.mediapipe_cache/hand_landmarker.task`。
3. 从 [MediaPipe 官方模型地址](https://storage.googleapis.com/mediapipe-models/hand_landmarker/hand_landmarker/float16/1/hand_landmarker.task) 下载到缓存。

下载使用临时文件，验证模型包完整后再替换缓存；下载失败可点击 **重连摄像头 / 模型** 重试。通过内存缓冲加载模型，支持中文项目路径和用户名。准备好模型后即可离线使用。

手部检测采用 [MediaPipe Hand Landmarker 的 Python Tasks 接口](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python)，使用真实单调时钟作为视频帧时间戳。

## 排错

- **摄像头不可用**：先关闭占用摄像头的会议 / 预览软件，检查 Windows「隐私和安全性 → 摄像头 → 允许桌面应用访问摄像头」，再切换编号或点击重连。浏览器不需要摄像头授权。
- **模型不可用**：查看面板中的具体错误。确认安装了 requirements 中的依赖，或手动放入模型。修复后点击重连。
- **摄像头拔插**：服务每隔约 3 秒尝试重连；期间可直接使用鼠标。
- **采集长时间卡住**：超过 2 秒未返回新帧会显示异常；先重连，若驱动阻塞导致重连无效，请关闭并重启服务。
- **有画面但没有骨架**：在「出刀与跟随」中选择「识别灵敏度 → 较高（推荐）」并应用；仍有漏检可试「更高」。完整露出手掌与手指，保持正面光照，避免遮挡或手部太小。点击「重连摄像头 / 模型」会重新创建识别器，即使没有报错也会清除旧跟踪状态；背景出现误识别时调回「标准」。更新代码后先关闭旧服务再启动，刷新页面。
- **快速挥手时丢手**：新版已加入当前画面补检与连续刀轨修复，更新后需关闭旧服务并重启 `start.bat`。若预览中的手已明显模糊，可改善正面照明、保持整手在画面内，再适当减小挥动幅度；单纯提高目标帧率不能保证摄像头曝光或模型处理更快。
- **暂未收到新的手部坐标**：这是识别结果更新超时，与「未发现手部」不同；检查服务状态和推理耗时，必要时重连。
- **有骨架但不出刀**：先选择「追踪位置 → 手掌中心」和「出刀方式 → 跟手出刀」，点击应用。伸指和捏合为可选操作，不是移动刀片的必要条件。
- **选食指 / 中指后仍跟着掌心**：Ctrl+F5 加载新版页面，追踪位置现在选择即应用；看到「当前追踪：食指指尖 / 中指指尖」后，预览光圈和刀锋应跟随对应指尖。旧版只改下拉框后点击「完成」不会保存；若显示应用失败，重新选择重试。
- **不清楚手与刀的位置关系**：游戏右上角展开「你的手 → 刀锋」，查看手部光圈和对应连线；镜像开启时左右同向，操作框对应整个游戏画面。上下、左右移动整只手掌，把刀锋光圈或银色刀刃贴到水果上。
- **左右反了 / 够不到边缘**：先确认镜像，再标定操作范围；也可手动调整横纵灵敏度和中心偏移。
- **已识别但刀贴边不动 / 看不到刀**：刷新页面加载修复；在「操作范围」点击「恢复全画面」，避免放大的映射把手部活动区压到屏幕边缘。丢手时游戏会明确显示识别提示，可打开设置检查画面。
- **想使用独立骨架窗口**：先停止游戏服务，再运行 `.venv\Scripts\python.exe backend/preview.py --camera 0`，按 Q / Esc 退出，避免同时抢占摄像头。
- **端口被占用**：同项目服务会自动复用；其他程序占用时关闭该程序，或使用 `--port 8001`。
- **全局 pip 提示 `~umpy`**：这是原 Anaconda 环境中的无效分发记录；启动器已使用项目虚拟环境，不自动修改全局安装目录。
