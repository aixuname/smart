# 项目审查、后续优化与排错清单

审查日期：2026-10-16。对象：当前 Python / MediaPipe / aiohttp / Phaser 单人版。

## 结论与检查范围

正常单人流程的基础检查和浏览器回归通过。下一轮最有价值的工作是补齐异常恢复与设置一致性、修正出界计分，再依据现场测量优化延迟。现有结果不足以证明各种摄像头、光照和长时间运行都稳定。

本轮新增审查报告和复现探针，以下发现尚未修复。没有改动游戏生产代码、依赖或用户的 `backend/settings.json`；浏览器诊断使用临时设置的本机服务，本轮没有打开物理摄像头。

| --- | --- | --- |
| 启动与环境 | 批处理、独立环境、端口复用、设备锁、依赖 | 当前环境正常；代理和失效环境恢复存在缺口 |

## 已确认的问题与建议顺序

“优先”表示下一轮建议先修，“随后”表示特定使用条件下再处理；不表示所有玩家都会遇到。

### 1. 优先：摄像头抛出读帧异常时，自动恢复分支没有执行

**触发与影响：** 摄像头曾正常工作，随后 `cap.read()` 连续抛异常。异常被统一记为“识别失败”，旧 capture 没有释放；自动重开条件要求 capture 为空，因此会一直复用坏句柄。读帧返回 `False` 的路径已有恢复，不能与抛异常的路径混为一谈。

**证据：** mock 成功 1 帧后连续失败 6 次，模拟经过 6.6 秒，设备仍只打开一次；显式“重连摄像头 / 模型”能够重开并恢复。尚未用实际设备拔插证明具体驱动会进入此分支。

**定位：** [gesture_server.py](backend/gesture_server.py) 第 362、368、399–403 行。

**建议：** 分开处理采集异常与推理异常；采集异常释放设备并进入现有退避重连流程。原生驱动一直不返回属于另一类问题，需另测退出和隔离策略。

**当前排查：** 错误持续超过约 3 秒时点击重连；仍不恢复则关闭服务、检查连接和占用，再启动。不要只反复刷新浏览器。

### 2. 优先：多页面设置冲突，以及关闭面板后的保存失败不易察觉

**触发 A：** 页面 A 选择食指后保持设置页打开，页面 B 将服务改为中指。A 已收到中指配置，却仍显示“当前追踪：食指指尖”。A 再只修改平滑算法并点应用，会把整个旧表单提交，追踪点重新变成食指。

**触发 B：** 改追踪位置后立即点“完成”，若请求失败，错误只写入已隐藏的面板；重新打开还会清空错误。已复现服务保留掌心、界面失败信息不可见的情况。正常请求成功时，“选择即应用”仍然有效。

**证据：** [设置探针报告](artifacts/audit-settings-report.json)，使用实际浏览器和临时服务；保存失败由 HTTP 500 注入。

**定位：** [GestureSettings.js](frontend/js/GestureSettings.js) 第 27–36、117–156、222 行；[main.js](frontend/js/main.js) 第 118 行。

**建议：** 界面以实际应用的配置更新状态；只提交修改过的字段，必要时用版本检测冲突；关闭面板后仍显示保存失败，或“完成”等待保存结果。把“选择即应用”和“需点应用”的两种交互进一步统一，避免再次误解。

**当前排查：** 只保留一个游戏页面；看见“当前追踪”再关闭设置。出刀方式、平滑、摄像头等其他参数仍需点“应用识别设置”。疑似不生效时重新打开面板检查服务读取的实际值。

### 3. 优先：窄屏横向飞出的水果没有按限时规则扣 5 分

**触发与影响：** 水果先横向越界，被生成器回收；随后漏切检查只看仍然活动的物体，因此跳过扣分。计分结果会受屏幕形状影响。

**证据：** 用真实 Edge / Phaser，设置当前生成器允许的初速度，水果未被切中。320×844 时从侧面离场后分数仍为 20；1280×900 对照正常降为 15。详见 [浏览器报告](artifacts/audit-gameplay-report.json)。另一个代码探针证明直接越过底部 `h+120` 也会绕过扣分，但未证明普通低帧率必然触发该状态。

**定位：** [FruitSpawner.js](frontend/js/core/FruitSpawner.js) 第 90–100 行；[GameScene.js](frontend/js/scenes/GameScene.js) 第 157–160、253–268 行。

**建议：** 将“漏果计分”和“回收原因”统一处理，再关闭物体，保证侧边和底部离场都只结算一次。仅交换现有两个调用的顺序，不能解决只检查底边的问题。

**当前排查：** 用限时模式，先取得正分，再观察窄屏横向离场的未切水果；应扣 5 分。无尽模式漏果本来不扣机会，炸弹漏掉也不应算水果漏切。

### 4. 随后：代理会干扰本机服务检测

配置了 HTTP 代理但未绕过 `127.0.0.1` 时，本机身份检查也走代理，可能导致服务已正常启动却不自动打开网页，重复启动被误报端口冲突。本机代理 fixture 已复现：不绕过返回 False，绕过后同一服务返回 True。

**定位：** [instance.py](backend/instance.py) 第 30 行；[main.py](backend/main.py) 第 38–42、63–70 行。

**建议与排查：** 仅让固定本机地址的健康检查绕过代理，模型下载仍遵循用户网络配置。现在可先手动打开终端给出的地址；页面能开却提示端口冲突时，检查代理的本地地址绕过规则。

### 5. 随后：项目迁移后失效的虚拟环境无法自动恢复

如果把现成 `.venv` 复制到其他机器，或原基础 Python 被卸载/移动，`python.exe` 可能仍存在但不能运行。启动器会把这种情况误报为版本过低；用有效 Python 执行 `setup_env.py` 也会因旧环境存在而失败。已在独立临时目录复现，当前工作环境正常。

**定位：** [start.bat](start.bat) 第 8、19–20 行；[setup_env.py](setup_env.py) 第 15–21 行。

**建议与排查：** 检查解释器能否实际执行，区分环境损坏和版本不符；给出保留旧环境后重建的流程。迁移时重建环境，不把已有 `.venv` 当成可直接运行的发布包。

### 6. 随后：服务端 WebSocket 没有检查 Origin

带不相关 Origin 请求头的本机客户端可以订阅状态、设置与控制点，而同一 Origin 的 POST 被拒绝。已验证服务端缺少这一检查；未验证任意浏览器网站都能连接，浏览器的本地网络与混合内容限制仍需单独确认。没有通过此接口取得摄像头 JPEG。

**定位：** [gesture_server.py](backend/gesture_server.py) 第 67–70、155–157 行。

**建议：** 在握手前验证来源，明确无 Origin 的本机测试客户端策略，并继续保持默认只监听本机。

### 7. 低优先级的工具与输入边界

- 独立 [preview.py](backend/preview.py) 第 149–152 行：持续读帧失败会跳过键盘处理，Q / Esc 无效。只影响独立骨架窗口；可用启动终端的 Ctrl+C 退出。失败分支也应轮询退出键并显示状态。
- [gesture_tracking.py](backend/gesture_tracking.py) 第 40–42 行：极大整数会抛 `OverflowError`。接口应返回 400 却返回 500；同样内容手工写入设置文件会阻断启动。正常页面不会生成这类值；运行中服务和旧设置未被破坏。建议统一数值校验错误处理，配置载入失败时回退默认值。

## 已发现的条件风险与还值得做的优化

### 识别体验与延迟

- **先补可观测性。** 显示同帧补检次数/成功率、实际吞吐、丢手次数和重新识别耗时。现有 `recovery_attempts` / `recovery_successes` 只在引擎内部，现场看不到。
- **区分 FPS 与延迟。** 当前 FPS 平滑的是帧间隔倒数；建议补“窗口内完成帧数 / 窗口时长”。`frame_age_ms` 只表示距离最近成功读帧返回有多久，不是摄像头曝光到屏幕的延迟；`dispatch` 也不包括浏览器渲染。
- **保留补检，但测量代价。** 本轮照片回放中，开启补检的整段推理 P50/P95 为 29.34/81.35ms，关闭为 11.00/22.69ms；测试顺序和机器负载并未隔离，不能把全部差值归因于补检。此前同项目结果较低，说明还需要固定负载对照与目标设备验收。
- **改善暗光/模糊提示。** 快速位移可恢复不等于运动模糊可恢复。优先给出整手入镜、距离、照明与光圈位置的明确反馈，再评估亮度/手部尺寸/模糊提示的误报率。
- **只在测到积压后拆线程。** 如果目标电脑确实存在推理阻塞采集，可考虑采集与推理分离、仅保留最新一帧；同时验收设备释放、切换和退出。当前检查不足以支持立刻更换整个技术栈。

### 延迟消息与设备故障

代码探针表明：两条生成于 5 秒前的连续手势消息，若现在才到达，会被按接收时间当成新消息并产生切线。正常本机传输中是否发生尚未测量，后端的最新帧队列和发送超时已减少部分积压。

建议在连接会话、消息序号和来源时间有效性上增加保护，过旧消息应断轨丢弃。跨机器使用前需处理时钟差，不能直接相减不同起点的单调时钟。见 [前端专项报告](artifacts/audit_frontend_notes.md)。

## 你可以照着执行的排错清单

先只开一个服务、一个游戏页面，保持窗口大小不变，记下所选追踪点与出刀方式。每次只调整一个设置，便于确认原因。

| 检查项 | 怎么操作 | 正常表现 / 异常时看哪里 |
| --- | --- | --- |
| 启动环境 | 双击 start.bat；失败时分别看系统 Python 与项目 Python 版本 | 项目解释器能运行；只有项目解释器失败时查 `.venv/pyvenv.cfg`，不要只反复安装新 Python |
| 页面与端口 | 打开终端显示的本机地址，默认 http://127.0.0.1:8000 | 能打开但没有自动弹浏览器，优先查代理；端口占用时先确认是否旧游戏服务 |
| 摄像头 | 看预览是否更新，检查设备编号；关闭占用设备的软件 | 有实时画面；无画面查设备、系统权限、编号、占用，不先调识别阈值 |
| 有画面但没有手 | 整手正对镜头、适当靠近、正面照明；使用“较高”灵敏度并应用 | 出现骨架/光圈；背景误识别时调回标准 |
| 三种追踪位置 | 手掌尽量不动，依次选食指、中指、掌心，再单独屈伸相应手指 | 指尖模式随对应指尖变化；掌心模式不因单个指尖屈伸大幅移动；看“当前追踪”和预览光圈 |
| 出刀开关 | 分别试跟手、伸指、捏合；改出刀方式后点应用 | 跟手持续出刀；伸指/捏合未满足时应能移动但不切；追踪点和出刀开关是两个设置 |
| 手与刀的位置 | 缓慢走四角，再做两点标定 | 镜像开启左右同向、刀尖能覆盖画面；够不到边缘先恢复全画面；切追踪点后重新确认标定 |
| 快速挥动与丢手 | 慢移、快速折返各做几次；移出画面再入镜 | 真正丢手停刀；恢复不横扫旧位置；若预览中手明显模糊，先改善照明，再看推理耗时 |
| 接触与切割 | 分别用刀尖光圈、银刃擦水果，静止等待水果碰刀 | 激活时接触应切开；刀柄不切；关闭出刀或无手时不切；同时确认不是暂停/演示/鼠标在操作 |
| 限时计分 | 取得正分后，放过一个水果；分别观察底部和窄屏侧边离场 | 都应扣 5 分且最低为 0；侧边漏扣是本次已确认的问题，不是识别问题 |
| 暂停与切后台 | 设置暂停约 3 秒，再恢复；切换标签页再返回 | 游戏倒计时、连击计时不消耗暂停时间；恢复不跨屏误切 |
| 设备恢复 | 外接摄像头可在测试时断开再接回；观察错误、等待、重连 | 返回 False 的故障可自动恢复；异常不恢复时点重连；原生调用卡死可能仍需重启服务 |
| 保存与刷新 | 改追踪点、确认后刷新；其他参数点击应用后再重开 | 实际值保留；失败时先重新打开看真实值；不要用两个页面同时调参 |
| 排行榜 | 保存成绩后刷新，同一浏览器、同一地址再次打开 | 本地存储正常则保留；隐私模式/存储受限可能仅当前会话有效；不同端口不会共享同一份浏览器存储 |
| 长时间使用 | 玩 30 分钟，每 10 分钟记录一次异常和性能 | 不持续恶化；重点记录卡顿发生时是否开预览、是否快速挥手、是否切过设置 |

### 不用摄像头的基础检查

在项目根目录执行：

```powershell
.venv\Scripts\python.exe --version
.venv\Scripts\python.exe -m pip check
.venv\Scripts\python.exe -X utf8 tests/run_checks.py
.venv\Scripts\python.exe -X utf8 tests/model_smoke.py
.venv\Scripts\python.exe -X utf8 tests/model_motion_smoke.py
```

核心检查需要 Node；模型检查使用已有本地模型。摄像头单独检查前先关闭正在占用摄像头的游戏服务，然后执行：

```powershell
.venv\Scripts\python.exe -X utf8 tests/camera_smoke.py
```

它会打开默认摄像头约 12 秒并输出状态，不保存画面。测试期间把手放入镜头；重点看 `camera_ok`、`model_missing`、`error`、`visible_hand_frames` 和预览响应。该脚本输出诊断结果，不能仅凭退出码判定所有条件合格。

### 报错时记录这些信息

- 症状和具体操作顺序：是否快速移动、切点、开设置、切后台或刚插拔设备。
- 当前模式、追踪位置、出刀方式、镜像、映射范围、浏览器窗口尺寸。
- 设置页完整错误文字；终端报错末尾；是否同时开了另一服务或页面。
- 同一次故障的 `/api/status` 中 `camera_ok`、`model_missing`、`error`、`revision`、`applied_revision`、`frame_age_ms` 和各阶段 P50/P95。
- 能否通过鼠标继续玩，重连是否有效，是否必须重启服务。无需记录或上传摄像头画面。
