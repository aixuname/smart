# 第 8 周：AI 编程工具配置

> 本周不写新语法。目标只有一个：**让每个人电脑上真正跑通一套 AI 编程工具，并安全地用起来。**

[讲义目录](./README.md) · [← 上一周：第 7 周](./第07周_Pandas进阶与可视化.md)

## 本周目标

学完这一周，你应该能：

- 说清 Codex CLI、Claude Code、CC Switch 三者分别是什么、怎么配合。
- 独立在自己电脑上装好并验证这套工具。
- 配置好供应商（API Key），并且能随时切换或换回。
- 知道它的能力边界：什么该交给它、什么必须自己确认。
- 说出至少三条安全和成本上的注意事项。
- **本周产出**：在自己的第 7 周项目上，让 AI 成功改好 1 处代码。

## 一、为什么要学这个

前面七周你学的所有东西，都是「自己把代码写出来」。而现在的真实工作方式已经变成：

> **你负责想清楚要什么、判断对不对；AI 负责把代码敲出来。**

对你来说这不是偷懒，而是把时间从「记语法」挪到「想问题」上。但前提是：

1. 你得**看得懂**它写的代码——所以前七周不能跳。
2. 你得会**配好工具**——不然每次卡在装环境上。
3. 你得知道它**什么时候在胡说**——这叫「审稿能力」，比写作能力更重要。

## 二、三个工具是什么关系

| 工具 | 是什么 | 打个比方 |
| --- | --- | --- |
| **Codex CLI** | 命令行的 AI 编程助手，能读你的项目文件、改代码、跑命令 | 一个坐在你旁边的程序员 |
| **Claude Code** | 同类工具，另一个厂商出的 | 另一个程序员 |
| **CC Switch** | 跨平台桌面应用，统一管理上面这些工具的**供应商配置** | 一个「换卡器」/ 遥控器 |

关键要理解的是：Codex CLI 和 Claude Code **本身不带模型**，它们要连一个「供应商」才能干活。而配置供应商过去要手动改 `settings.json`、`config.toml`、`.env` 这些文件——又难又容易错，**CC Switch 就是来替你改这些文件的**。

- [CC Switch 项目地址](https://github.com/farion1231/cc-switch)
- [CC Switch 下载页](https://www.ccswitch.io/zh/download)

CC Switch 目前支持管理 Claude Code、Codex、Gemini CLI、OpenCode、OpenClaw 这几类工具的配置，内置了几十个供应商预设，选好预设、填上 Key、点「启用」就生效。

## 三、课前准备（装机清单）

**这五件事必须在课前三天的做完**。课上只做「配置 + 验证」，现场装环境一定装不完。

- [ ] 安装 **Node.js（LTS 版本）**，装完打开终端能显示版本号
- [ ] 配置 npm 国内镜像源
- [ ] 安装 **Codex CLI**
- [ ] 下载并安装 **CC Switch**
- [ ] 拿到一个可用的 **API Key**（课上统一发）

### 1. 装 Node.js

去 [nodejs.org](https://nodejs.org) 下载 **LTS** 版本，一路下一步。（Codex CLI 通过 npm 安装，npm 是 Node.js 自带的。）

装完**新开一个终端窗口**（重要，旧的终端读不到新的环境变量），验证：

```bash
node -v      # 例如 v20.11.0
npm -v       # 例如 10.2.4
```

> 看不到版本号说明装失败或没配好 PATH。**先解决这个再往下走**，不要跳。

### 2. 换 npm 国内镜像源

```bash
npm config set registry https://registry.npmmirror.com
npm config get registry      # 确认已生效
```

不换源的话，装包可能卡十几分钟甚至超时。

### 3. 安装 Codex CLI

```bash
npm install -g @openai/codex
codex --version
```

### 4. 安装 CC Switch

从 [GitHub Releases](https://github.com/farion1231/cc-switch/releases) 或 [官网下载页](https://www.ccswitch.io/zh/download) 下载 Windows 安装包，双击安装。

### 5. 准备 API Key

课上统一发。**拿到后自己保存好，不要发群里、不要提交进代码仓库。**

## 四、课上流程（每步验证通过再往下）

### 第 1 步：确认 Node 环境

```bash
node -v
npm -v
```

### 第 2 步：确认 Codex CLI 装好了

```bash
codex --version
```

### 第 3 步：在 CC Switch 里配置 Codex

1. 打开 CC Switch。
2. 顶部或侧边的**应用切换器**里，选中 **Codex**。
3. 点 **+** 添加供应商。
4. 在「预设」下拉里选择课上指定的供应商。
5. 把 API Key 粘贴到对应字段。
6. 点「添加」，然后点这张卡片上的「**启用**」——卡片出现「当前启用」标记才算成功。

> CC Switch 会自动把配置写进 Codex 的配置文件，**你不需要手动改任何 json/toml**。这就是它存在的意义。

### 第 4 步：验证能用

打开终端，进到你有代码的目录（比如第 7 周的项目文件夹）：

```bash
cd 你的项目目录
codex
```

进去后先问一句最安全的问题：

```
解释一下这个文件在做什么
```

能正常回答 = 配置成功。

### 第 5 步：换成 Claude Code 再来一遍

1. 在 CC Switch 里把应用切换到 **Claude**，同样添加供应商并启用。
2. 终端里运行 `claude`。
3. Claude Code 支持热重载——**切换供应商不用重启终端**。Codex 则建议重开一个终端窗口再试。

### 第 6 步：讲心智模型（比命令重要）

> **它不是搜索引擎，是一个会读写你文件的同事。**

所以正确的用法是：

| 做法 | 说明 |
| --- | --- |
| ✅ 先让它**读** | 「先解释一下这个文件，不要改」 |
| ✅ 再让它**改** | 「把图表的标题改成中文，只改这一处」 |
| ✅ **小步**验证 | 一次只改一件事，改完自己跑一遍 |
| ✅ 用 **Git 兜底** | 改之前 `git commit`，改坏了 `git checkout .` |
| ❌ 一上来就丢整个工程 | 「帮我优化一下这个项目」→ 它可能改 20 个文件 |
| ❌ 不看结果直接信 | 「已经修好了」≠ 真的修好了 |

### 第 7 步：实战（40 分钟）

用第 7 周的综合项目做素材，按顺序完成：

1. **读**：「解释一下这个脚本每一步在做什么」
2. **改一处**：「给柱状图加上中文标题和数值标签，只改画图那部分」
3. **解释报错**：故意把 `encoding="utf-8"` 删掉，让它解释报错并修复
4. **自己验证**：跑一遍，确认结果和你预期一致

## 五、常见报错排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `node: 无法将"node"项识别为...` | Node 没装好 / 终端没重开 | 重开终端；重装 Node 并勾选「Add to PATH」 |
| `npm: 无法将"npm"项识别为...` | 同上 | 同上 |
| `npm install -g` 卡住或超时 | 没换国内源 | `npm config set registry https://registry.npmmirror.com` |
| `codex: command not found` | npm 全局安装目录不在 PATH 里 | 看第六节「PATH 修法」 |
| `npm ERR! code EACCES` / 权限错误 | 没有写入全局目录的权限 | Windows 用管理员身份重开终端再装一次 |
| `npm ERR! code EPERM` | 文件被占用 / 杀毒软件拦截 | 关掉占用程序或临时关杀毒后重装 |
| 401 / 403 / 认证失败 | Key 错、余额不足、供应商没启用 | 在 CC Switch 里检查 Key 和「当前启用」状态 |
| 429 / 请求过多 | 触发限流 | 等一会儿再试，或换供应商 |
| CC Switch 里切了但没生效 | Codex 需要重开终端 | 关掉终端窗口重新打开；Claude 一般热重载即可 |
| 终端里中文乱码 | 控制台编码问题 | 先运行 `chcp 65001` 切到 UTF-8 |
| 连不上 / 一直转圈 | 网络问题 | 检查网络；确认供应商可访问 |

### PATH 修法（`command not found` 的通用解法）

```bash
npm config get prefix
```

把这个命令输出的路径加到系统环境变量 `Path` 里，然后**重开终端**。Windows 上一般是 `C:\Users\你的用户名\AppData\Roaming\npm`。

> **改环境变量必须重开终端**——这是零基础同学最容易忽略的一步，占了「明明装好了却用不了」的一大半。

## 六、安全与成本（必讲）

### 安全

- **API Key 是密码。** 不进代码仓库、不发群、不截图外传、不写进共享文档。
- 提交前扫一眼：`git status` 确认没有把 `.env`、`config.toml` 之类的东西加进去。
- **不要给它整个磁盘的权限。** 只在具体项目目录里用（`cd` 到项目再启动）。
- 涉及个人隐私、学号身份证、成绩原文的数据，不要交给它处理。
- 学校或公司有规定的，按规定来。

### 成本

- 每一轮对话都在**消耗 Token、都在花钱**。上下文越长越贵。
- 小问题用聊天窗口问；只有真的要改文件、跑命令时才用命令行工具。
- 一个话题聊完就**开新会话**，别让上下文无限变长。
- 在 CC Switch 里可以看用量统计，**第一周每天看一眼花了多少**。

### 兜底习惯（最重要的两条）

```bash
git commit -m "改之前先存档"     # 让它动手之前
git checkout .                   # 改坏了，一键回到存档
```

> 只要你会这两条，就永远不怕 AI 把代码改坏。**这是本周最值钱的两个命令。**

## 七、课堂练习（40 分钟）

1. **验证环境**：截图 `node -v`、`npm -v`、`codex --version` 三条输出。
2. **读代码**：让 AI 解释你第 7 周项目里最复杂的一个函数，然后**自己核对**它说得对不对。
3. **改一处**：让 AI 给柱状图加中文标题 + 数值标签，只允许改画图部分。
4. **故意找茬**：把 `encoding="utf-8"` 删掉运行，看报错，让 AI 解释并修复。
5. **回退练习**：把 AI 的改动 `git checkout .` 撤销掉，确认文件恢复原状。

- 故意给它一段有细微 bug 的代码问「这段代码对吗」。

然后记录下来：它是直接照做、还是指出了问题。**这个作业的目的是让你建立「它会犯错」的直觉。**

## 十、本周之后

这套工具以后会一直用。建议接下来一个月：

1. 每天至少用它解决一个真实小问题（不是玩，是干活）。
2. 每周看一次用量，别让成本失控。
3. **永远保持一个习惯**：它改完，你自己看一遍、跑一遍。

> 工具的价值不在于「AI 替你写」，而在于你从「不会写」变成「能判断写得对不对」。这个转变需要前面七周的地基，别丢。
