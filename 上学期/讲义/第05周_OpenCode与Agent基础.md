## 一、为什么现在学这个

前四周你已经能自己写代码了。现在要学的是**怎么和 AI 一起写**，因为真实的工作方式已经变了：

> 你负责想清楚要什么、判断对不对；AI 负责把代码敲出来。

但请注意顺序：**先会写，才能判断它写得对不对。** 前四周的地基不是可跳过的前置，而是本周的审稿能力来源。

## 二、三个层次：Chat → 补全 → Agent

很多同学以为「AI 编程」就是打开聊天窗口问问题。其实有三层，能力差别很大：

| 层次 | 代表 | 它做什么 | 你能得到什么 |
| --- | --- | --- | --- |
| **Chat 问答** | 网页版聊天 | 你贴代码，它回答 | 思路、解释、一段代码片段 |
| **补全** | 编辑器里的自动补全 | 猜你下一行要写什么 | 写得更快的单行代码 |
| **Agent 代理** | OpenCode / Codex CLI / Claude Code | **自己读文件、自己改文件、自己跑命令** | 一个被改好的项目 |

关键差别在最后一列：前两个给你「文本」，Agent 给你「结果」。因为它不只能说话，还能**动手**。

### Agent 的四个要素

理解 Agent，记住这四个词就够了：

| 要素 | 是什么 | 在你身上的类比 |
| --- | --- | --- |
| **模型** | 大语言模型，负责「想」 | 你的脑子 |
| **工具** | 读文件、写文件、执行命令、搜索 | 你的手和眼睛 |
| **上下文** | 它能看到的全部信息（对话、文件内容、项目规则） | 你手边摊开的资料 |
| **循环** | 想 → 做 → 看结果 → 再想，直到完成 | 你反复试错的整个过程 |

一个常见误区：以为它一次就能给出完美答案。实际上 Agent 的工作方式是**一轮一轮试出来的**——执行命令、看到报错、再改、再跑。所以报错不是失败，是它的正常输入。

> 这就是为什么「它会犯错」不是 bug，而是设计前提。你的任务是当那个**验收的人**。

## 三、OpenCode 是什么

[OpenCode](https://opencode.ai/zh) 是一个开源的 AI 编码代理，和 Codex CLI、Claude Code 是同一类工具。它有三种形态：

| 形态 | 说明 | 适合谁 |
| --- | --- | --- |
| **终端 TUI** | 在终端里运行的交互界面 | 推荐，功能最全 |
| **桌面应用** | 独立窗口的程序 | 不习惯命令行的同学 |
| **IDE 扩展** | VS Code / Cursor / Zed / Windsurf 插件 | 已经习惯在编辑器里工作 |

安装前需要准备：**一个现代终端**（Windows Terminal 就行）和**一个模型提供商的 API Key**。

## 四、安装

### 方式一：终端版（推荐）

```bash
# 官方安装脚本（macOS / Linux / WSL）
curl -fsSL https://opencode.ai/install | bash
```

Windows 上更简单的是走 npm（你第 3 周已经装过 Node.js 了）：

```bash
npm install -g opencode-ai
opencode --version        # 验证装好了
```

> 官方还提供了 `choco install opencode`、`scoop install opencode` 等方式，Windows 上也能用。官方**推荐 WSL** 以获得最佳体验，但零基础阶段先用原生 Windows 完全够用，别一上来就折腾 WSL。

### 方式二：桌面版

去 [下载页](https://opencode.ai/zh/download) 选 **Windows (x64)**。

**注意一个坑**：桌面版是**一键安装包，没有选目录的步骤**，会固定装到：

```
C:\Users\<你的用户名>\AppData\Local\Programs\@opencodedesktop
```

官方明确表示不会提供自定义目录（见 [Issue #26791](https://github.com/anomalyco/opencode/issues/26791)）。如果你的 C 盘紧张，装完后把它搬到别的盘再建一个目录联接就行：

```powershell
# 1. 彻底退出 OpenCode（含托盘图标）
# 2. 移动
Move-Item "$env:LOCALAPPDATA\Programs\@opencodedesktop" "D:\Apps\@opencodedesktop"
# 3. 建联接，让系统以为它还在原地
cmd /c mklink /J "$env:LOCALAPPDATA\Programs\@opencodedesktop" "D:\Apps\@opencodedesktop"
```

> 注意：卸载时要先删 C 盘那个联接，再手动删掉 D 盘的目录，否则会残留几百 MB。

### 方式三：IDE 扩展

在 VS Code / Cursor 的扩展市场里搜 OpenCode 安装即可，装完在编辑器侧边栏使用。

## 五、跑通第一次对话

### 第 1 步：配置模型提供商

```bash
cd 你的项目目录
opencode
```

在 TUI 里输入：

```
/connect
```

然后选一个提供商，填入 API Key。**没有 Key 的话，OpenCode 官方提供了 OpenCode Zen**（一组官方测试过的精选模型），按提示去 `opencode.ai/auth` 注册即可，对零基础最省事。

### 第 2 步：初始化项目

```
/init
```

OpenCode 会分析你的项目，在根目录生成一个 **`AGENTS.md`**，记录项目结构和你希望它遵守的规范。

> **这个文件要提交到 Git。** 它相当于你给 AI 的「入职须知」，团队共享。

### 第 3 步：开始用

| 操作 | 作用 |
| --- | --- |
| `@` | 模糊搜索并引用项目里的文件 |
| **Tab** | 在**计划模式**和**构建模式**之间切换 |
| `/undo` | 撤销它刚做的一批修改 |
| `/redo` | 重做被撤销的修改 |

**最关键的操作是 Tab。** 计划模式下它只给方案、**不动文件**；构建模式下才真正动手。

> 强烈建议：**任何改动都先走计划模式**。看它打算改哪些文件、怎么改，确认无误再切构建模式。这一步能挡掉 80% 的「它把我的代码改乱了」。

### 第 4 步：撤销

```bash
/undo      # 不满意就撤回
```

加上 Git 兜底，你就永远不会被改崩：

```bash
git commit -m "AI 动手前先存档"
git checkout .          # 兜底回退
```

## 六、Prompt：写清楚，它才做对

这周真正的技能点。**同一个模型，Prompt 好坏能让结果天差地别。**

### 四要素模板

```
【目标】我要什么
【上下文】相关文件在哪、现在是什么情况
【约束】不许改什么、用什么写法、保持什么风格
【验收标准】怎么判断做完了
```

### 对比

❌ **差的 Prompt**

```
帮我优化一下这个脚本
```

结果：它可能改 5 个文件、动你没让它动的地方，而且「优化」的标准是它自己猜的。

✅ **好的 Prompt**

```
【目标】让 analyze.py 能处理缺失值
【上下文】数据在 data/scores.csv，score 列有空值；脚本在 analyze.py，
         现在直接算平均分，遇到空值会得到 NaN
【约束】只改 analyze.py，不要动其他文件；用 pandas 的 fillna，
       填充方式用该列均值；保持现有函数结构
【验收标准】脚本能跑通，输出平均分是数字，并打印填充了几条
```

### 几条实用技巧

| 技巧 | 说法 |
| --- | --- |
| **先让它复述** | 「先用一句话复述我要你做什么，不要动手」 |
| **先让它列清单** | 「列出你打算修改的文件和原因」 |
| **给它例子** | 「参考我第 20 行的写法」 |
| **限定范围** | 「只改第 15–30 行」 |
| **允许它问** | 「需求不明确时先问我，不要猜」 |
| **一次一件事** | 改 bug 和加功能分两次说 |

> **千万别做的三件事**：说「帮我优化一下」、一次要求改十个地方、不看结果直接往下走。

## 七、Skill：把重复的要求存起来

### 是什么

Skill（技能）就是**一份可复用的说明书**：把一段你反复要提的要求写成文件，AI 在需要时自动加载。

举例：你每周都要让它「按我的规范写一份数据分析脚本：读 CSV、检查缺失、出两张图、写结论」。这段话每次都要重打，还容易漏。→ 写成 Skill，以后一句话就够。

### 和 AGENTS.md 的区别

| | `AGENTS.md` | `SKILL.md` |
| --- | --- | --- |
| 生效方式 | **始终生效**，一直躺在它的上下文里 | **按需加载**，需要时才读进来 |
| 适合放什么 | 项目通用规范（目录结构、代码风格） | 具体的、成流程的任务（某类固定操作） |
| 篇幅 | 短，越短越好 | 可以长，因为不占日常上下文 |

一句话：**AGENTS.md 是「公司规章制度」，Skill 是「操作手册」。**

### 怎么写

放在这个位置（项目级）：

```
.opencode/skills/<技能名>/SKILL.md
```

全局技能放 `~/.config/opencode/skills/<技能名>/SKILL.md`。OpenCode 还兼容 Claude 的 `.claude/skills/` 和 `.agents/skills/`。

文件必须以 YAML frontmatter 开头，**只有两个字段是必填的**：

```markdown
---
name: weekly-data-report
description: 把一份 CSV 生成标准的周报分析脚本：检查缺失值、分组统计、出两张图、输出结论。
---

## 我要做什么

输入：用户给的 CSV 路径。
输出：一个 `report.py` + 一段 Markdown 结论。

## 执行步骤

1. 用 pandas 读入，先打印 `shape`、`info()`、`isna().sum()`
2. 缺失值：数值列用均值填充，文字列填「未知」，并**打印填充了多少条**
3. 至少做一次 `groupby` 分组统计
4. 画两张图：柱状图 + 直方图，中文标题，`plt.savefig` 保存
5. 最后写出 3 条以内的结论，并说明数据局限性

## 硬性要求

- 所有绘图前必须设置中文字体
- 不要修改原始 CSV
- 代码要有中文注释
```

### 两条命名规则（写错就不会被加载）

- `name`：**全小写字母和数字**，可以用单个连字符连接，长度 1–64，且**必须与文件夹名一致**。正则：`^[a-z0-9]+(-[a-z0-9]+)*$`
- `description`：1–1024 字符，**要写得具体**——它是 AI 判断「什么时候该用这个技能」的唯一依据。写「处理数据」没用，写「把 CSV 生成周报分析脚本，含缺失值处理与两张图」才有用。

### 怎么知道它有没有生效

OpenCode 会把可用技能列在 `skill` 工具的描述里（`<available_skills>`）。你也可以直接问：「你现在有哪些技能可用？」

排查清单：
1. 文件名必须是 `SKILL.md`（**全部大写**）
2. frontmatter 里必须有 `name` 和 `description`
3. `name` 必须和文件夹名一致
4. 权限没被设成 `deny`

> `opencode.json` 里可以用 `permission.skill` 控制每个技能是 `allow`（直接加载）/ `ask`（问你）/ `deny`（隐藏），支持 `internal-*` 这样的通配符。初学不用管，知道有这回事就行。

## 九、常见问题排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `opencode: command not found` | npm 全局目录不在 PATH | `npm config get prefix`，把该路径加进系统 `Path`，**重开终端** |
| 启动后一直要求登录 | 没有配置提供商 | 用 `/connect` 配置，或选 OpenCode Zen |
| 401 / 403 | Key 错误、余额不足 | 重新 `/connect` 检查 Key |
| 429 / 请求过多 | 触发限流 | 等一会儿再试，或换模型 |
| 它改了一堆不该改的文件 | 没用计划模式 / Prompt 太模糊 | 先 Tab 切计划模式；Prompt 写清「只改 xx 文件」 |
| 改完代码跑不起来 | 没有自己验证 | 用 `/undo` 撤销，重写 Prompt 再来；Git 兜底 |
| 技能列表里没有我的 Skill | 文件名或 frontmatter 不合规 | 检查 `SKILL.md` 大写、`name` 与目录名一致 |
| 桌面版装到 C 盘了 | 一键安装包，官方不提供选目录 | 见第四节「搬到 D 盘 + 建联接」 |
| 终端中文乱码 | 控制台编码 | 先 `chcp 65001` |

## 十、安全与成本（必讲）

- **API Key 是密码**：不进仓库、不发群、不截图外传。提交前 `git status` 看一眼。
- **只在项目目录里启动**，不要给它整个磁盘的权限。
- **每一轮对话都在花钱**，上下文越长越贵；一个话题聊完就开新会话。
- **改之前先 commit**，改坏了 `git checkout .`。
- **不要相信「已经修好了」**——一定要自己跑一遍。
- 涉及个人隐私、学号身份证的数据，不要交给它。
